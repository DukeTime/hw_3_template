# Как проверить проект

В исходном Compose сервис Redis уже был, но приложение фактически работало с SQLite. Я оставил исходный `app.py`, структуру и стиль файлов, а в конфигурацию добавил то, чего не хватало по заданию: подключение к Redis, проверки готовности, ограничения процесса и автоматический сценарий.

## Результаты

Проверил на Docker Desktop 4.43.1, Engine 28.3.0 и Compose 2.38.1. `./scripts/check.sh` успешно прошёл два раза подряд. В каждом запуске сценарий:

- создал отдельный проект с пустым Redis и получил начальный счётчик 0;
- сделал 3 запроса на увеличение, значение стало 3;
- проверил, что значение 3 сохранилось после `docker compose down` и повторного запуска, а также после пересоздания только приложения;
- при остановленном Redis получил `healthz=200`, `readyz=503`, `increment=503`;
- после запуска Redis без перезапуска приложения увидел сохранённое значение 3 и следующее значение 4;
- создал резервную копию и проверил, что архив читается;
- удалил тестовый Compose-проект вместе с его volume.

Оба полных вывода сохранены в `logs/check-run-1.txt` и `logs/check-run-2.txt`. В `logs/docker-logs.txt` — логи базового запуска приложения и Redis. Сам резервный архив сценарий создаёт рядом с приложением при каждом запуске; для сдачи проекта этот временный файл не нужен.

Порт 8000 уже был занят во время первой ручной проверки; ручной запуск прошёл на 18088. Автоматический сценарий использует отдельный порт 18080.

## Запуск

В каталоге `app` скопируйте `.env.example` в `.env`, затем выполните `docker compose up -d --build`. Приложение будет доступно на порту из `HOST_PORT`. `docker compose down` сохраняет данные, а `docker compose down -v` удаляет volume.
